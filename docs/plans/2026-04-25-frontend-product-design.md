# brake-calc 前端产品设计结论（V1）

> 基于 `2026-04-23-input-yaml-frontend-ui.md` 与 2026-04-25 访谈整理。
> 本文档用于冻结前端产品定义、信息架构与交互边界，供后续前端实施计划与开发使用。

## 1. 目标与边界

前端 V1 的目标不是重新定义 brake-calc 业务，而是把已冻结的 V1 输入契约、已完成的 storage/backend 能力，以及已验收的 report 口径，组织成一个适合机械设计工程师使用的中文 Web 工作台。

前端必须完成四件事：

1. 编辑完整 V1 输入配置
2. 调用 backend 做权威校验
3. 保存、打开、导入、导出配置版本
4. 运行计算并消费结构化 `report`

前端不做：

- 业务计算
- report 推导
- YAML 权威校验
- 持久化协议定义
- 超出 V1 的业务扩展

必须严格服从：

- `AGENTS.md`
- `specs/Brake_Calc_ Workflow_Spec_v1.0.md`
- 当前已冻结 V1 输入契约
- 当前已验收 report / Markdown 口径

## 2. 用户与核心使用场景

主要用户是机械设计工程师，通常没有代码背景。

核心使用场景只有两条：

1. 新建项目，从空白开始完成首轮配置并运行
2. 打开既有配置，在已有结果基础上补充后置信息或发起修订并重新计算

辅助场景：

- 导入外部 YAML 形成可编辑配置
- 导出 YAML 给业务负责人排查或留档

因此产品主入口应优先服务“新建项目”和“打开既有项目”，而不是以 YAML 文件操作为中心。

## 3. 总体产品形态

前端采用“配置工作台 + 顺序引导”的混合模式：

- 新用户可按步骤顺序完成配置
- 熟练用户可在工作台内自由跳转章节
- 结果页与配置页之间支持快速往返

推荐目录位置维持既有计划假设：`frontend/`。

## 4. 页面结构与信息架构

### 4.1 首页 / 列表页

首页主入口：

- `新建项目`
- `打开既有项目`
- `导入 YAML`（辅入口）

项目/配置列表最重要的信息：

- 项目名称 / 编号
- 最近修改时间
- `controller_type`

### 4.2 新建项目初始化流程

点击“新建项目”后，不直接进入完整空白大表单，而是先走一个简短初始化流程：

1. 先填写 `project_name`、`project_code`
2. 选择 `controller_type = bogie / car`
3. 输入简化编组信息，用于自动生成初始 `vehicle_config`

进入工作台后：

- 默认落在“运行基础配置 / 技术条件”章节
- 初始 `vehicle_config` 由模板生成
- 用户可继续微调实例列表

### 4.3 配置工作台

工作台采用三栏结构：

- 左侧：章节导航与状态标记
- 中间：当前章节表单
- 右侧：校验错误、YAML 预览、局部运行/结果摘要

YAML 预览定位：

- 面向高级用户核对
- 不是主要编辑入口
- 不支持直接手改 YAML 作为主流程

### 4.4 章节组织

中间主表单按“计算流程”分章，而不是按技术实现分层：

1. 项目基础信息
2. 运行基础配置 / 技术条件
3. 车辆与控制器配置
4. 载荷与空簧
5. 基础制动机械参数
6. 停放校核
7. 标定
8. 电制动特性
9. 结果页

其中：

- `停放校核`
- `标定`
- `电制动特性`

都属于 V1 范围，但不应被强制纳入所有新建项目的首轮必经路径。

## 5. 新建、打开、修订、补充的流程定义

### 5.1 新建项目主路径

新建项目首轮计算的默认主路径是“先完成主制动计算”，而不是强制同时完成停放校核、标定和电制动特性录入。

因此前端要支持：

- 先完成主制动相关必填项
- 先跑出第一轮结果
- 后续再补充停放校核、标定、电制动特性

### 5.2 打开既有项目后的默认状态

对于“已运行成功”的既有项目，打开后默认进入 `只读总览`，不是直接进入可编辑状态。

总览页定位是工作台入口页，不是完整配置详情页。

总览页最重要的信息：

- 最后一次运行时间 / 状态
- 警告与自动调整
- 是否已补充停放校核

并提供三个后置补录快捷入口：

- `补充停放校核`
- `补充标定`
- `补充电空计算`

这里“电空计算”是业务侧习惯叫法；V1 产品语义仍严格落在 `electric_brake` 输入补录与摘要查看，不表示已接入主计算。

### 5.3 只读、补充、修订三种状态

前端需明确区分三种状态：

1. `只读基线`
2. `补充后置信息`
3. `正式修订`

在默认只读态下：

- 主配置章节锁定
- 左侧导航仅开放停放校核、标定、电制动特性三章
- 总览页提供三项快捷入口

### 5.4 修订机制

若用户需要修改主配置，不能直接改当前已运行成功版本，必须显式点击 `修订`。

修订行为定义为：

- 自动基于当前版本创建一个新版本副本
- 用户在副本上编辑、保存、运行
- 原版本保持不变

修订副本必须记录：

- 来源版本
- 修订时间
- 修订原因 / 说明

V1 预置修订原因：

- 外部条件变更
- 标定更新
- 补充停放校核
- 增加电空计算

## 6. 章节级产品定义

### 6.1 运行基础配置 / 技术条件

本章应先讲“技术条件目标”，再展开制动类型配置。

组织顺序：

1. 技术条件目标
2. 制动类型
3. 各制动类型对应的 `requirement` / `response_time`

制动类型交互规则：

- `FSB`、`EB` 必含
- `FB` 与自定义 `ratio_of_FSB` 的初始显示由初始化向导决定
- 进入工作台后仍可继续增减可选类型

### 6.2 车辆与控制器配置

`vehicle_config` 录入不应强迫用户从空白逐条手建实例。

推荐方式：

- 初始化阶段用简化编组信息快速生成
- 进入工作台后允许逐条微调

### 6.3 载荷与空簧

这是最高风险章节，必须优先投入解释和防错设计。

页面策略：

- 页面顶部先解释“这一页在算什么、这些值通常来自哪里”
- 关键字段旁必须有简短中文说明和单位提示
- 最关键的 1 到 2 句默认展开，详细说明折叠

章节内部顺序：

1. `mass_params`
2. `air_spring`

#### `mass_params` 录入原则

按类型分块：

- `powered_bogie`
- `trailer_bogie`

每个类型块内再按 `AW0 / AW2 / AW3` 组织。

需要特别处理录入口径差异：

- `bogie_weight` 通常来自单个转向架口径
- `mass_static` 在业务资料中常见整车口径

因此前端应支持 `mass_static` 两种录入口径：

- 按整车录入
- 按转向架录入

交互要求：

- 用明确切换控件选择录入口径
- 默认推荐“按整车录入”
- 切换后字段标签、说明文字、口径提示同步变化
- 同页强提示：`bogie_weight` 始终是单个转向架口径

当 `controller_type = car` 时：

- 不应把质量参数改造成整车专属另一套概念
- 仍保留 bogie 类型级参数录入
- 但必须明确提示：车控模式下系统会按一车两转向架聚合

#### `air_spring` 录入原则

先选输入模式，再展示对应字段：

- 特征点拟合
- 显式线性公式

不预设某一种为绝对主流默认。

若使用特征点拟合，必须强提示坐标轴单位，尤其是横轴质量单位风险：

- 压力轴：`kPa`
- 质量轴：`ton`

由于业务资料里有时会给 `kN`，此处是高风险误填点。

前端设计结论倾向支持横轴单位辅助切换：

- `ton / kN`

若支持 `kN`，前端仅做录入辅助换算，不改变后端权威输入口径。该点需在实施前再次确认不突破 V1 契约边界。

### 6.4 基础制动机械参数

这是第二高风险章节，核心问题不是流程，而是“单位多、参数多、停放缸与制动缸容易混”。

因此：

- 单位必须强提示，不能只藏在 placeholder
- 页面说明需明确区分制动缸参数与停放缸参数
- 停放缸参数不得混入本章

### 6.5 停放校核

停放校核是独立章节，且默认不干扰新建项目首轮主路径。

本章定位：

- 默认服务“后置补录”
- 也支持快速回看当前是否已配置、是否完整、结果如何

页面结构：

1. 顶部状态摘要
2. `环境条件`
3. `机械参数`

### 6.6 标定

标定章节必须按 `载重工况` 组织，而不是优先按 `service_brake / emergency_brake` 组织，因为现场试验与补录流程是按载重工况展开的。

页面结构：

- `aw3_aw0`
- `aw3_aw2`

每个工况块内：

1. 先显示当前状态摘要（未配置 / 部分配置 / 已完整配置）
2. 再进入对应点表与模式编辑

本章要同时支持：

- 首次补录
- 多轮修订
- `aw3_aw0` 与 `aw3_aw2` 交替更新

### 6.7 电制动特性

V1 范围内，本章的核心价值不是参与主制动计算，而是：

- 补录 `electric_brake` 输入
- 查看电机特性
- 通过图表快速理解电制动曲线

页面应轻量但直观：

- 上方展示电制动曲线
- 下方展示特性点表

## 7. 保存、校验、导入、导出、运行

### 7.1 保存

默认心智：

- 用户可随时保存草稿
- `保存` 只保存配置，不触发计算

### 7.2 运行

运行是单独动作。

点击“运行”后：

- 系统自动执行权威校验
- 校验通过才真正运行
- 运行成功后自动切换到结果页

### 7.3 导入 YAML

导入 YAML 是辅助场景，主要服务于“高级用户或业务负责人提供 YAML，工程师将其导入为系统内可编辑配置”。

导入成功后，不直接进入编辑页，而是先进入导入摘要页。

导入摘要页优先展示：

- 是否包含停放校核 / 标定 / electric_brake 等后置内容
- 是否存在导入警告
- 是否可直接运行

### 7.4 下载 YAML

下载 YAML 的主要用途：

- 发给业务负责人排查问题
- 留档
- 配置快照交接

它不是普通工程师的日常编辑入口。

## 8. 结果页设计结论

### 8.1 结果首屏优先级

结果首屏不能只围绕压力矩阵。

优先级应为：

1. 顶部摘要
2. 制动性能检查
3. 压力矩阵
4. 其他结构化结果

### 8.2 顶部摘要

最显眼的结论优先级：

1. 是否存在校验/运行警告
2. 是否触发自动调整
3. 是否满足技术条件

### 8.3 制动性能检查

第一块主结果应服务“是否满足技术条件”的判断。

需优先展示：

- 控制减速度
- 不同初速度下的理论制动距离 / 平均减速度检查

控制减速度不必单独再做一块卡片，可直接并入同一张检查表。

### 8.4 压力矩阵

压力矩阵仍是核心结果，但放在制动性能检查之后。

由于不同角色关注视角不同：

- 设计者更关注按 `brake_type`
- 调试者更关注按 `load_group`

因此结果区宜提供：

- 默认紧凑总表
- 视角切换能力

### 8.5 结果页与配置页往返

运行成功后自动进入结果页。

结果页应同时提供：

- 顶部 `返回配置`
- 章节导航直接跳转相关配置章节

## 9. 错误提示与防错设计

### 9.1 错误提示语言

必须使用中文。

### 9.2 错误提示结构

采用两层结构：

1. 顶部业务化中文结论
2. 可点击定位的字段错误清单

### 9.3 运行前失败文案

分两类处理：

- 缺失/未填：`当前配置还不能运行，请先补全以下信息`
- 格式/逻辑冲突：`配置校验失败，请修正以下字段错误`

### 9.4 错误定位方式

三层同时存在：

- 左侧章节导航显示错误状态
- 右侧错误清单支持点击跳转
- 中间字段旁显示中文错误提示

### 9.5 失败后的辅助动作

运行失败后，应在失败提示附近强调两个动作：

- 中文错误摘要
- 下载当前 YAML

便于用户把配置和错误一起发给业务负责人排查。

## 10. V1 设计取舍与优先级

前端 V1 的优先级不是“先做漂亮复杂的交互”，而是：

1. 主流程必须走通
2. 易错区必须讲清楚并做强防错

如果要取舍，优先保证以下区域的解释和防错质量：

- 载荷与空簧
- 基础制动机械参数

## 11. 对实施计划的影响

后续前端实施计划必须继承本文档，而不是回退到旧版假设。

与旧计划相比，必须显式吸收以下新增结论：

- 主流程是“新建项目 + 打开既有配置”
- 已运行成功项目默认进入只读总览
- 存在“只读 / 补充 / 修订”三种状态
- 修订必须创建新版本副本，不直接覆盖旧版本
- 停放校核、标定、电制动特性属于后置补录章节
- 结果首屏以制动性能检查优先，不以压力矩阵优先
- `mass_static` 需支持整车/转向架两种录入口径
- `air_spring` 特征点必须强提示单位风险

## 12. 待后续实施前再次确认的点

以下点已经形成产品倾向，但在真正进入实现前还需要再做一次契约/实现方式确认：

1. `mass_static` 双录入口径是前端显示层转换，还是 backend 接口显式支持两种口径
2. `air_spring` 特征点横轴是否允许 `kN` 辅助录入，以及换算职责由哪一层承担
3. 只读基线、补充后置章节、修订副本在 backend storage/API 上的状态表达方式
4. “最后一次运行状态”“是否已补充停放校核”等总览指标由哪一个 backend 接口统一提供
