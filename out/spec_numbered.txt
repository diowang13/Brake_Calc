1: # 城轨制动计算 Workflow Spec（v1.0 草案）
2: 
3: <aside>
4: 📌
5: 
6: 这份文档是你这个“制动力计算 skill”的**确定性工作流 Spec**（面向 Codex 实现与 Hermes 调用）。
7: 
8: - 基础力-压力转换系数 `k_initial` 与初闸压力 `BCP0_initial` 不作为用户输入显式配置；由 `mech_params` 与 `n_cylinders_by_controller` 在 S7 内部推导
9: - 调试后：S8 可选按载荷组（AW0/AW3 必须，AW2 可选）、制动模式和 controller 目标制动力启用 `k(f)` 标定曲线，并按载荷组与制动模式选择固定 `BCP0`
10: </aside>

12: ## 1. 输出位置与使用方式
13: 
14: - 本 spec 将作为项目的“唯一真相来源”（single source of truth）
15: - Codex：按本 spec 的模块接口与 workflow 顺序实现 Python 模块，并在本地进行项目调试。
16: - Hermes：后续部署到云端服务器，由Hermes按本 spec 的 inputs/配置加载并执行 workflow，输出压力标准与追溯信息。
17: 
18: ## 2. 目标输出（Outputs）
19: 
20: ### 2.1 主要输出
21: 
22: - `report`：最终结构化报告对象，包含压力标准、理论速度检查、控制器开发参数、校核结果、告警、自动调整记录、限幅事件与 trace
23: - `BCP_calibrated_by_controller` / `controller_pressure_standards`：每个控制器的目标控制压力/压力标准，单位 `kPa`
24:     - 输出按**实验条件载荷**（AW0 / AW2 / AW3）× **制动类型向量**（见 Inputs `brake_types`）组织，形成压力标准矩阵
25:     - 结构示意：`BCP_calibrated_by_controller[load_group][brake_type][controller] = pressure`
26: - Markdown 报告：CLI 可通过 `--markdown-output <path>` 导出 Markdown；PDF 暂不作为内置输出，由外部工具从 Markdown 转换
27:     - V1 Markdown 报告至少包含：
28:       - 顶层标题固定为：`Summary / Key Tables / Checks / Controller Development Parameters`
29:       - `Summary`：配置摘要与自动调整记录
30:       - `Key Tables`：`Pressure / Dynamic Load Matrix` 紧凑矩阵，同时展示动态载荷、空簧压力和各制动类型 BCP
31:       - `Checks`：理论速度检查、停放制动力校核结果、电制动摘要
32:       - `Controller Development Parameters`：`Calibration Summary`、动态载荷公式、压力转换参数、力到压力公式
33:       - `delta_BCP` 保留为结构化兼容字段，但不作为 Markdown 主视图展示
34: 
35: 
36: ### 2.2 必须可追溯的中间量
37: 
38: - `Beta_list`：控制用目标减速度向量
39:     - 与 Inputs 中的 `brake_types` 一一对应，每个元素为该制动类型下的控制用目标减速度
40:     - 其中：
41:       - **紧急制动（EB）**的控制减速度由运动学方程（结合 `requirement` 与 `response_time.t1/t2`）计算得出
42:       - **最大常用制动（FSB）**的控制减速度由运动学方程（结合 `requirement` 与 `response_time.t1`、`response_time.impulse_rate` 联立求解）
43:       - **快速制动（FB）**不单独反求控制减速度，直接取 `Beta_FB = Beta_EB`
44:     - 其余用户自定义类型（如保持制动、跳跃制动）按其配置的 FSB 百分比直接缩放得到：`Beta[type] = ratio * Beta[FSB]`
45: 
46: - `Mass_by_controller`：按控制器聚合的静态质量 / 动态制动质量向量
47:     - 维度：`[load_group] × [controller]`
48:     - 架控时，动态质量的计算依赖该控制器对应转向架实例的 `bogie_type`（`powered_bogie` / `trailer_bogie`）
49:     - 车控时，动态质量的计算依赖该控制器对应车辆实例的 `car_type`（`powered_car` / `trailer_car`），并按一车两转向架聚合质量与转动惯量
50: 
51: - `F_by_controller`：每控制器目标制动力 f（kN）
52: - `k_initial`：S7 由机械模型推导的理论基础力-压力转换系数，单位 `kPa/kN`
53: - `BCP0_initial`：S7 由机械模型推导的理论初闸压力，单位 `kPa`
54: - `BCP_base_by_controller`：基础模型压力（未调试标定），按 `BCP_base = k_initial * F_by_controller + BCP0_initial` 计算
55: - `k_used_by_controller`：S8 最终实际使用的力-压力转换系数，单位 `kPa/kN`
56: - `BCP0_used_by_controller`：S8 最终实际使用的初闸压力，单位 `kPa`
57: - `AirSpringPressure_by_controller`
58:     - 维度：[load_group] × [controller]
59:     - 单位：kPa
60: - `AirSpringFit_by_bogie_type`
61:     - 维度：`[bogie_type]`
62:     - 内容：`{k, b, source_mode}`
63:     - 单位：`kPa/ton`、`kPa`
64:     - 含义：记录每类转向架采用的空簧线性公式，`source_mode` 取值为 `fitted_from_points` 或 `explicit_linear`
65: - `auto_adjustments`
66:     - 内容：自动采取的策略调整记录
67:     - 示例：等磨耗自动切换为等黏着、`FB` 压力超过 `EB` 后自动提高 `BCP0_EB`
68: - `CalibrationSummary`
69:     - 内容：标定试验点、生成的 `k_sb(f)` / `k_eb(f)`、最终生效的 `BCP0` / `BCP0_for_code`、输入标定点、最终曲线边界点、分段 `k_for_code` 公式，以及面向控制器开发的分段曲线图
70:     - 当 `controller_type = car` 时，V1.0 的 `CalibrationSummary` 不生成车控 EB 的 `k_eb(f)` 曲线和分段公式，只展示限制提示与基础压力结果来源。
71: - `ParkingBrakeCheckResult`
72:     - 内容：停放制动力校核结果
73:     - 包括：每车双侧作用力、每车停放制动力、每车倾斜力、每车安全余量、整列停放制动力、整列倾斜力、整列安全余量、是否通过
74:     - 字段语义：
75:       - `F_N_PB` = 单个制动单元闸片/瓦块双侧作用力（kN）
76:       - `F_PB` = 每车停放制动力（kN）
77:       - `whole_train` = 整列汇总停放制动力与倾斜力
78:     - S9 兼容保留 `parking_brake_check_result`，正式逐载荷组输出写入 `parking_brake_check_results_by_load_group`
79: - `ElectricBrakeSummary`
80:     - 内容：电制动特性输入摘要
81:     - 包括：是否启用、力值定义范围、识别出的特性点前若干项和末若干项
82: 
83: ## 3. 关键工程规则（必须满足）
84: 
85: 1. **载荷 AW0/AW2/AW3 仅用于选择参数组**，运行时不做组间插值
86: 2. **标定曲线 `k(f)` 的自变量为单 controller 目标制动力 f**，即 `k = k_of_f(load_group, brake_mode, F_by_controller)`；不使用全列总力
87: 3. **S7 机械模型参数与 S8 调试标定参数分离**：S7 推导 `k_initial` 与 `BCP0_initial`，S8 可选使用调试后的 `k(f)` 与 `BCP0` 计算最终压力
88: 4. **车控 EB 标定限制（V1.0）**：当 `controller_type = car` 时，紧急制动不使用 `emergency_brake` 的 `k(f) / BCP0` 试验点标定；车控 EB 实际 BCP 压力标定留待 V1.1。V1.0 不得静默套用架控 EB 标定逻辑。
89: 5. 校准不回写到 μ 或机械模型本体；只影响输出侧压力标准
90: 6. 所有模式必须应用阀件限幅（如 EB 的 min/max）并在 report 中记录限幅触发
91: 
92: ## 4. Inputs（输入参数，待你后续补齐单位/范围/默认值）
93: 
94: - `schema_version`：输入契约版本号。V1 固定为 `1`，用于后续配置迁移与兼容性控制。
95: - `v0`：最高速度（技术条件定义点）
96: - `V_list`：可选速度列表，单位 `km/h`，用于 S9 输出 `theoretical_speed_checks`。未配置时仅使用 `v0`；V1 对 `FSB`、`EB`、`FB` 生成理论速度检查，`ratio_of_FSB` 类型不单独生成。
97: - `requirement`：基础制动类型的技术条件输入
98:   - `FSB`：仅接受平均减速度要求 `a_mean`
99:   - `EB`：可接受平均减速度要求 `a_mean` 或制动距离要求 `distance`
100:   - `FB`：不单独配置 `requirement`，其控制目标减速度直接取 `EB`
101:   - `ratio_of_FSB` 类型不单独配置 `requirement`
102:   
103: - `brake_types`：制动类型向量，定义本次计算需要输出的所有制动类型
104:     - **必含项**：最大常用制动 `FSB`、紧急制动 `EB`
105:     - **可选项 1 — 快速制动 `FB`**
106:         - 行业内通常用 `Fast Brake` 指代快速制动
107:         - `FB` 的控制目标减速度直接等于 `EB` 的控制目标减速度，即 `Beta_FB = Beta_EB`
108:         - `FB` 的制动力分配策略强制为 `equal_adhesion`
109:         - `FB` 的响应模型使用常用制动形式（`t1 + impulse_rate`）
110:     - **可选项 2 — 用户自定义制动类型**
111:         - 一般以「最大常用制动 FSB 的百分比」形式定义
112:         - 例：保持制动 `holding = 50% FSB`
113:         - 例：跳跃制动 `jerk = 10% FSB`
114:     - 建议结构：
115:       ```yaml
116:       brake_types:
117:         - name: FSB
118:           source: kinematic
119:         - name: EB
120:           source: kinematic
121:         - name: FB
122:           source: fast_brake
123:         - name: holding
124:           source: ratio_of_FSB
125:           ratio: 0.5
126:       ```
127: 
128:         
129: - `response_time`：响应时间，按制动模式分别给出：
130:   - `FSB`
131:     - `t1`：空走时间（dead time）
132:     - `impulse_rate`：减速度上升率，单位 `m/s^3`
133:     - `t2` 不作为输入；由于其与控制减速度相互依赖，需在 `response_compensation` 中联立求解
134:   - `EB`
135:     - `t1`：空走时间（dead time）
136:     - `t2`：建立时间（build-up time），从开始产生减速度到减速度达到目标值 90% 的时间
137:   - `FB`
138:     - `t1`：空走时间（dead time）
139:     - `impulse_rate`：减速度上升率，单位 `m/s^3`
140:     - `FB` 不单独计算控制减速度，但需要在理论速度检查中使用该响应模型
141:   - `ratio_of_FSB` 类型不单独配置响应参数，直接沿用 FSB 的派生结果进行缩放
142: 
143: - 在 `response_compensation` 模块中：
144:   - `EB` 使用距离扣除模型，结合 `t1` 和 `t2` 由 `a_mean_req` 反推控制用目标减速度
145:   - `FSB` 使用距离扣除模型，结合 `t1` 和 `impulse_rate` 联立反求控制用目标减速度
146:   - `FB` 不单独反求控制目标减速度，直接取 `Beta_FB = Beta_EB`；但在 S9 理论速度检查中，仍使用 `FB` 自身的响应模型（`t1 + impulse_rate`）计算不同初速度下的理论制动距离与平均减速度
147: 
148: 
149: - `controller_type`：控制器粒度，取值为 `bogie` / `car`
150:   - 当 `controller_type = bogie` 时，一个 controller 对应一个转向架
151:   - 当 `controller_type = car` 时，一个 controller 对应一辆车
152: - `n_bogies_by_controller`：每个 controller 对应的 bogie 数量，关联 `controller_type`
153:   - `bogie` 时为 1
154:   - `car` 时为 2
155: - `n_springs_by_controller`：每个 controller 对应的空簧数量，关联 `controller_type`
156:   - `bogie` 时为 2
157:   - `car` 时为 4
158: - `n_cylinders_by_controller`：每个 controller 对应的制动缸数量，关联 `controller_type`
159:   - `bogie` 时为 4
160:   - `car` 时为 8
161: 
162: - `load_groups`：实验条件载荷组，取值为 AW0 / AW2 / AW3
163: - `air_spring`：支持空簧特征点和显式公式两种空簧特性输入。根据特征点拟合时不做分段线性，只收敛为单条直线 `pressure_kpa = k * sprung_mass_by_spring_ton + b`。运行时由 `sprung_mass = mass_static - bogie_weight` 得到控制器簧上质量，再按 `sprung_mass_by_spring_ton = sprung_mass / n_springs_by_controller` 计算单个空簧承担的簧上质量，并代入空簧公式。
164:   - fitted_from_points：输入若干 `[pressure_kpa, sprung_mass_by_spring_ton]`
165:   - explicit_linear：输入 airspring_k、airspring_b
166: - `mass_params`：转向架类型级质量参数，承载静态质量、转向架自重和旋转质量因子。`mass_static` 与 `bogie_weight` 均使用 `ton`，并在后续计算中保持 `ton`，不再换算为 `kg`。
167:   - 车控时，输入中的 `bogie_weight` 仍表示单个 bogie 自重；后台按一车两转向架聚合时乘 2
168:   - `powered_bogie` / `trailer_bogie` 的旋转质量参数（如 `rotational_mass_factor`）
169:   - 建议结构：
170:       ```yaml
171:         mass_params:
172:           powered_bogie:
173:             mass_static:
174:               AW0: ...
175:               AW2: ...
176:               AW3: ...
177:             bogie_weight: ...
178:             rotational_mass_factor: ...
179:           trailer_bogie:
180:             mass_static:
181:               AW0: ...
182:               AW2: ...
183:               AW3: ...
184:             bogie_weight: ...
185:             rotational_mass_factor: ...
186:         ```
187:   - 车控下 `powered_car` 对应两套 `powered_bogie` 参数，`trailer_car` 对应两套 `trailer_bogie` 参数
188: 
189: - `allocation_strategy`：制动力分配策略配置，可选一个：
190:     - `equal_wear`（等磨耗分配）：尽量在所有控制器上平均分配目标制动力
191:     - `equal_adhesion`（等黏着分配）：按各控制器控制范围内的载荷（`mass_dynamic`）比例分配
192:     - **适用规则**：
193:         - 紧急制动（EB）**必须**采用 `equal_adhesion`
194:         - 快速制动（FB）**必须**采用 `equal_adhesion`
195:         - 最大常用制动（FSB）及以 FSB 百分比定义的自定义类型按 `allocation_strategy` 配置执行
196:         - 若用户配置 `equal_wear` 但在当前载荷关系下超过全局黏着限制 `adhesion.mu_limit`，软件应自动切换为 `equal_adhesion`，并记录告警与自动调整信息
197: 
198: - `vehicle_config`：逐控制器实例配置，配置形态由 `controller_type` 决定
199:   - 当 `controller_type = bogie` 时，每个转向架实例对应一个控制器：
200:     - `name`
201:     - `bogie_type`：`powered_bogie` / `trailer_bogie`
202:     - 建议结构：
203:       ```yaml
204:       vehicle_config:
205:         bogies:
206:           - name: trailer_bogie_1
207:             bogie_type: trailer_bogie
208:           - name: powered_bogie_3
209:             bogie_type: powered_bogie
210:       ```
211:     - `trailer_bogie_1` 表示编号为 1 的拖车转向架实例
212:     - `powered_bogie_3` 表示编号为 3 的动力转向架实例
213:   - 当 `controller_type = car` 时，每辆车对应一个控制器：
214:     - `name`
215:     - `car_type`：`powered_car` / `trailer_car`
216:     - 建议结构：
217:       ```yaml
218:       vehicle_config:
219:         cars:
220:           - name: trailer_car_1
221:             car_type: trailer_car
222:           - name: powered_car_2
223:             car_type: powered_car
224:       ```
225:     - `powered_car` 表示该控制器控制一辆由两个动力转向架组成的车辆
226:     - `trailer_car` 表示该控制器控制一辆由两个拖车转向架组成的车辆
227:     - 若一辆车存在动架与拖架混合，则业务上不采用车控 BCU，而改用架控
228: - 静态质量不在实例层配置；实例的 `bogie_type` 或 `car_type` 用于到 `mass_params` 中读取对应类型参数
229: 
230: - `mass_static` = `sprung_mass` + `bogie_weight`
231: - `sprung_mass` = `mass_static` - `bogie_weight`    
232: - `mech_params`：制动缸机械模型参数，全列共享一套，用于在 S7 中由 `F_by_controller` 反算基础制动缸压力 `BCP_base_by_controller`，并内部推导基础力-压力转换系数 `k_initial`。V1 支持：
233:   - `cylinder_type: tread_cylinder`
234:   - `cylinder_type: caliper_cylinder`
235:   - 制动缸数量不在 `mech_params` 中重复配置，统一使用顶层 `n_cylinders_by_controller`
236:   - 通用字段建议结构：
237:     ```yaml
238:     mech_params:
239:       cylinder_type: tread_cylinder   # or caliper_cylinder
240:       Sc: 0.0248     # 单位: m^2，活塞有效面积
241:       xi: 0.29       # 单位: -，摩擦系数
242:       Li: 3.4        # 单位: -，单元内部倍率
243:       eta_i: 0.95    # 单位: -，单元内部效率
244:       Lo: 1.0        # 单位: -，外部倍率
245:       eta_o: 1.0     # 单位: -，外部效率
246:       Fs1: 1.0       # 单位: kN，单元复位力 1
247:       Fs2: 0.25      # 单位: kN，单元复位力 2
248:       Dw: ...        # 单位: m，仅 caliper_cylinder 需要
249:       Rf: ...        # 单位: m，仅 caliper_cylinder 需要
250:     ```
251:   - `Fw` 暂不作为 YAML 接口暴露，V1 按 `Fw = 0` 处理
252:   - 对 `tread_cylinder`，标准公式中的 `Dw / (2 * Rf)` 按 1 处理，因此网页端不需要输入 `Dw` 和 `Rf`
253:   - 对 `caliper_cylinder`，必须显式配置 `Dw` 和 `Rf`
254: 
255: - `pressure_calibration`：可选压力标定配置，用于 S8 输出侧标定。V1 采用**试验点驱动**方式输入，不要求用户直接维护完整 `k_segments`。标定分为常用/快速制动体系与紧急制动体系；其中车控项目 V1.0 仅支持 `service_brake` 标定，不支持 `emergency_brake` 标定。
256:   - `service_brake`：生成常用/快速制动共用的 `k_sb(f)` 与 `BCP0_sb`
257:   - `emergency_brake`：仅架控项目使用，生成紧急制动独立的 `k_eb(f)` 与 `BCP0_eb`
258:   - 两组都支持两种点组合方式：
259:     - `aw3_aw0`
260:     - `aw3_aw2`
261:   - 试验点输入建议结构：
262:     ```yaml
263:     pressure_calibration:
264:       enabled: true
265:       service_brake:
266:         BCP0: 25.0
267:         point_pair_mode: aw3_aw0
268:         points:
269:           - load_group: AW0
270:             brake_type: FB
271:             k_for_code: 1050
272:           - load_group: AW3
273:             brake_type: FSB
274:             k_for_code: 1200
275:       emergency_brake:
276:         BCP0: 30.0
277:         point_pair_mode: aw3_aw0
278:         points:
279:           - load_group: AW0
280:             brake_type: EB
281:             k_for_code: 1100
282:           - load_group: AW3
283:             brake_type: EB
284:             k_for_code: 1250
285:     ```
286: 
287: - `parking_brake_check`：停放制动力校核输入，仅用于校核，不参与常用/紧急/快速制动压力标准计算。建议结构：
288:   ```yaml
289:   parking_brake_check:
290:     enabled: true
291:     required_safety_margin: 1.2
292:     static_friction_coefficient: 0.35
293:     n_parking_cylinders_by_car: 1
294:     cylinder:
295:       Fp: 8.75
296:       Fs1: 1.2
297:       Fs2: 0.15
298:       Lpi: 2.04
299:       eta_pi: 1.0
300:       Lo: 1.0
301:       eta_o: 1.0
302:     environment:
303:       wind_speed_max: 34.0
304:       wind_resistance_coefficient: 0.0037
305:       grade_by_load_group:
306:         AW0: 40
307:         AW3: 40
308:     ```
309:   - 当前输入字段 `static_friction_coefficient` 在停车业务口径中承担 `xi0`
310:   - 停放制动力中的 `Lpi`、`Lo` 分别表示停放缸内部倍率与执行机构外部倍率；二者按公式单独参与计算，不与夹钳半径换算项混用
311:   - 另有制动形式相关的几何换算项 `brake_geometry_factor`：
312:     - `tread_cylinder`：`brake_geometry_factor = 1`
313:     - `caliper_cylinder`：`brake_geometry_factor = 2 * Rf / Dw`
314:   - 停放制动力公式口径：
315:     - `F_N_PB = ([(Fp - Fs2) * Lpi * eta_pi] - Fs1) * Lo * eta_o`
316:     - `F_PB = brake_geometry_factor * F_N_PB * Np * xi0`
317:   - `incline_force` 当前按“坡道项 + 风阻项”口径计算
318:   - 校核结果按 `parking_brake_check.environment.grade_by_load_group` 逐载荷组输出
319: 
320: - `adhesion`：全局黏着限制输入，供黏着校核与自动分配策略切换使用。建议结构：
321:   ```yaml
322:   adhesion:
323:     mu_limit: 0.16
324:   ```
325: 
326: - `electric_brake`：电制动特性输入预留，当前 V1 不参与主制动计算，仅保存识别后的结构化特性点。建议结构：
327:   ```yaml
328:   electric_brake:
329:     enabled: false
330:     force_scope: train_total
331:     characteristic_points: []
332:   ```
333: 
334: - force_scope 允许取值：
335:   - train_total
336:   - per_car
337:   - per_bogie
338:   - per_axle
339: 
340: - EB_limit_min：紧急制动输出最小压力值
341: 
342: - 压力限制规则：
343:   - EB max = 600
344:   - EB min = EB_limit_min
345:   - FSB/ratio_of_FSB/FB max = 当前载荷组下 EB 压力
346:   - FSB/ratio_of_FSB min = 无
347:   - FB 的最终压力不得超过 EB；若标定后 FB > EB，需自动提高 BCP0_EB 并重新计算 EB 压力标准

349: ## 5. 模块间数据契约（Context 模型）
350: 
351: > 本节只定义**数据契约**（字段/形状/单位/生产者-消费者），不规定传输实现（dict / pydantic / JSON / RPC 均可）。具体实现方式放到代码仓库的 `AGENTS.md`。
352: > 
353: 
354: ### 5.1 Context 原则
355: 
356: - 所有模块采用 `context_in → context_out` 语义，**追加式写入**（append-only），不得修改或覆盖上游已写字段
357: - 每个字段 key 在全局范围内唯一；一旦产出，下游只读引用
358: - 未消费的上游字段应**透传**到下游，以保证端到端可追溯
359: - 所有数值字段必须带**单位**（见下表），工程量纲不一致时需在 `validate_inputs` 中统一化
360: - 若计算过程中发生自动策略调整，必须保留原始输入语义，并把“实际使用配置”以独立字段（如 `auto_adjustments`）追加写入 context，不得覆盖上游输入
361:

417: ### 5.4 错误 / 告警 / 追溯通道
418: 
419: - `warnings`：非致命情形写入，如 k 超标定范围、AW2 使用 fallback、限幅触发、超黏着后强制改用等黏着、`FB` 压力超过 `EB` 后自动上调 `BCP0_EB` 等；每条含稳定的 `code` 便于机器判定
420: - `auto_adjustments`：记录软件自动采取的策略调整，需保留原始用户输入与最终实际使用配置之间的差异，例如：
421:   - `equal_wear -> equal_adhesion`
422:   - `BCP0_EB` 自动提高
423: - `clamp_events`：阀件限幅的事件流，记录限幅前/后值，供 `summarize_and_checks` 统计
424: - `trace`：由 runner（本地调试或 Hermes）写入，每个 step 的输入 hash / 输出 key / 耗时，用于复跑比对
425: - **致命错误**（例如输入校验失败）应直接抛异常中止 workflow，不走 `warnings`

461: ## 6. Modules（模块接口定义）
462: 
463: > 每个模块都遵循：输入 `context` → 输出 `context`（添加字段，不破坏既有字段）
464: > 
465: 
466: 1) `validate_inputs`
467: 
468: - in: inputs
469: - out: validated_inputs
470: - 作用：对输入参数做结构/类型/单位校验与归一化，填默认值，产出后续模块可信赖的 `validated_inputs`；质量字段在输入、Context 和计算中统一使用 `ton`。V1 需覆盖 `controller_type = bogie | car`、`fast_brake`、`caliper_cylinder`、`parking_brake_check`、`adhesion`、`electric_brake` 以及新的试验点驱动标定结构。
471: 
472: 2) `derive_requirement`
473: 
474: - in: validated_inputs
475: - out: a_mean_req
476: - 作用：将技术条件 `requirement`（平均减速度 **或** 制动距离）统一换算成 `a_mean_req` —— 即各“运动学类”制动类型（当前为 `FSB`、`EB`）对应的平均减速度需求值；若输入为制动距离，在此处由 `v0` 和距离反算出等效平均减速度。`FB` 不单独进入 `a_mean_req`，而是在 S3 中直接继承 `Beta_EB`
477: 
478: 3) `response_compensation`
479: 
480: - in: validated_inputs（含 `brake_types`、`response_time`） + a_mean_req
481: - out: `Beta_list`（与 `brake_types` 顺序对应的控制用目标减速度向量）
482: - note:
483:     - 对 `source: kinematic` 的 `EB`：
484:       - 先由 `a_mean_req` 反算标准制动距离 `S = v^2 / (2 * a_mean_req)`
485:       - 再按距离扣除模型补偿响应损失：
486:         `Beta_EB = v^2 / (2 * (S - v * (t1_EB + t2_EB / 2)))`
487:     - 对 `source: kinematic` 的 `FSB`：
488:       - 先由 `a_mean_req` 反算标准制动距离 `S = v^2 / (2 * a_mean_req)`
489:       - 建立时间由冲击率决定，`t2_FSB = Beta_FSB / impulse_rate`
490:       - 与距离扣除模型联立求解控制减速度
491:     - 对 `source: fast_brake` 的 `FB`：
492:       - 不单独反求控制目标减速度
493:       - 直接取 `Beta_FB = Beta_EB`
494:       - 但后续在 S9 理论速度检查中，仍使用 `FB` 自身的响应模型（`t1 + impulse_rate`）
495:     - 若响应损失距离不小于标准制动距离，则该输入无物理可行解，应报错
496:     - 对 `source: ratio_of_FSB` 的用户自定义类型，直接按 `ratio * Beta[FSB]` 得到，不再单独做运动学补偿
497: 
498: 4) `calc_dynamic_load_and_mass`
499: 
500: - in: validated_inputs（由 `bogie_type` 或 `car_type` 去 `mass_params` 中读取质量参数、`air_spring`、`bogie_weight`）
501: - out: `Mass_by_controller`、`AirSpringPressure_by_controller`、`AirSpringFit_by_bogie_type`
502: - note:
503:     - 架控时，一个 controller 对应一个 bogie
504:     - 车控时，一个 controller 对应一辆车，按两个同类型 bogie 聚合：
505:       - `powered_car` = 两个 `powered_bogie`
506:       - `trailer_car` = 两个 `trailer_bogie`
507:     - 车控下：
508:       - `mass_static` 为整车级质量
509:       - `bogie_weight` 聚合时乘 2
510:       - `mass_dynamic` 为整车级动态制动质量
511:       - `n_springs_by_controller = 4`
512:     - 空簧压力公式始终输出**单个空簧压力标准**
513:     - 先算 `sprung_mass = mass_static - bogie_weight`
514:     - 再按 `sprung_mass_by_spring_ton = sprung_mass / n_springs_by_controller` 计算单个空簧承担的簧上质量
515:     - 动态制动质量按 `mass_dynamic = mass_static[load_group] + mass_static[AW0] * rotational_mass_factor` 计算，即旋转质量增量以同类型 AW0 静态质量为基准
516: 
517: 
518: 5) `calc_required_brake_force`
519: 
520: - in: `Beta_list` + `Mass_by_controller`
521: - out: `F_by_controller`（kN），按 `brake_type × load_group × controller` 组织
522: - note:
523:     - 各制动类型的总目标制动力均按 `F_kN = mass_dynamic_ton * Beta` 计算
524:     - `EB` 强制采用 `equal_adhesion`
525:     - `FB` 强制采用 `equal_adhesion`
526:     - `FSB` 及 `ratio_of_FSB` 类型：
527:         - 若 `allocation_strategy = equal_wear`，则各控制器平均分配
528:         - 若 `allocation_strategy = equal_adhesion`，则按各 controller 的 `mass_dynamic` 比例分配
529:     - 质量单位采用 `ton`，制动力单位采用 `kN`
530:     - 此处参与目标制动力计算与等黏着分配的质量均为 `mass_dynamic`
531: 
532: 
533: 6) `allocate_brake_force`
534: 
535: - in: `F_by_controller` + allocation_strategy + vehicle_config + adhesion
536: - out: F_by_controller（确认粒度与分配后的结构；如步骤 5 已按策略给出最终值，此步负责验证、约束修正与粒度规范化）
537: - 作用：校验分配结果是否满足设计约束，并统一输出粒度。
538: - note:
539:     - 对 `EB` 与 `FB`，必须使用 `equal_adhesion`
540:     - 对 `FSB` 与 `ratio_of_FSB`：
541:       - 若用户配置 `equal_wear`，先按等磨耗分配
542:       - 若校验发现超过全局黏着限制 `adhesion.mu_limit`
543:       - 则自动切换为 `equal_adhesion`
544:       - 写入 `warnings` 与 `auto_adjustments`
545:     - 输出中应保留原始配置与实际使用策略的差异信息，供 S9 汇总
546: 
547: 
548: 7) `force_to_pressure_base`
549: 
550: - in: `F_by_controller` + `n_cylinders_by_controller` + `mech_params`
551: - out: `k_initial` + `BCP0_initial` + `BCP_base_by_controller`
552: - 作用：按制动缸机械模型推导理论基础力-压力转换参数，并将每 controller 目标制动力 `F_by_controller`（kN）反算为未标定的基础制动缸压力 `BCP_base_by_controller`（kPa）。
553: - note:
554:     - `k_initial` 与 `BCP0_initial` 不作为输入显式配置，由 `mech_params` 与 `n_cylinders_by_controller` 内部推导
555:     - 支持两种基础制动形式：
556:       - `tread_cylinder`
557:       - `caliper_cylinder`
558:     - `Fw` 在 V1 中按 `0` 处理，不作为 YAML 输入
559:     - 对 `tread_cylinder`：
560:       - `Dw / (2 * Rf)` 按 1 处理
561:       - 网页端不需要输入 `Dw` 和 `Rf`
562:     - 对 `caliper_cylinder`：
563:       - 必须显式输入 `Dw` 和 `Rf`
564:       - 计算公式中保留 `Dw / (2 * Rf)` 项
565:     - 统一线性形式仍为：
566:       ```text
567:       BCP_base = k_initial * F_by_controller + BCP0_initial
568:       ```
569:     - 单位约定：
570:       - `F_by_controller`、`Fs1`、`Fs2` 使用 kN
571:       - `Sc` 使用 m²
572:       - 输出 `BCP_base` 为 kPa
573:     - `k_initial` 与 `BCP0_initial` 必须由当前 `mech_params` 与 `n_cylinders_by_controller` 实时计算，不设置、不读取、不校准为固定示例值
574: 
575: 
576: 8) `apply_pressure_calibration`
577: 
578: - in: `F_by_controller` + `BCP_base_by_controller` + `k_initial` + `BCP0_initial` + `pressure_calibration` + `EB_limit_min`
579: - out: `k_used_by_controller` + `BCP0_used_by_controller` + `BCP_calibrated_by_controller`
580: - 作用：可选应用调试标定参数，决定最终用于每个 controller 的 `k_used` 与 `BCP0_used`，计算最终压力标准并执行阀件限幅。
581: - note:
582:     - 若未启用标定，`k_used = k_initial`，`BCP0_used = BCP0_initial`
583:     - 若启用标定：
584:       - 常用/快速制动 (`FSB`、`FB`、`ratio_of_FSB`) 使用 `service_brake` 试验点生成的 `k_sb(f)` 与 `BCP0_sb`
585:       - 当 `controller_type = bogie` 时，紧急制动 (`EB`) 使用 `emergency_brake` 试验点生成的 `k_eb(f)` 与 `BCP0_eb`
586:       - 当 `controller_type = car` 时，V1.0 不支持 EB 的 `emergency_brake` 标定，EB 使用 S7 基础压力结果
587: 
588:     - 试验点生成规则：
589:       - AW0 取该工况下各 controller 制动力最大值作为力坐标
590:       - AW3 取该工况下各 controller 制动力最小值作为力坐标
591:       - AW2 取该工况下各 controller 制动力平均值作为力坐标
592:     - 支持两种点组合：
593:       - `aw3_aw0`
594:       - `aw3_aw2`
595:     - 对 `aw3_aw2`：
596:       - 常用/快速制动需要外推到 AW0 参考力点
597:       - 若项目启用 `FB`，则 AW0 参考力取 `AW0 + FB` 工况下各 controller force 的最大值
598:       - 若项目未启用 `FB`，则 AW0 参考力取 `AW0 + FSB` 工况下各 controller force 的最大值
599:       - 紧急制动的 AW0 参考力取 `AW0 + EB` 工况下各 controller force 的最大值
600:     - 架控项目生成的 `k_sb(f)` 与 `k_eb(f)` 必须是覆盖完整有效力区间的分段曲线，车控项目仅对`k_sb(f)`的分段曲线有相同要求：
601:       - 低力段常数
602:       - 中间段线性
603:       - 高力段常数
604:       - 不允许出现某个有效力值下无可用 k 的情况
605:     - 最终压力统一按：
606:       ```text
607:       BCP_calibrated = k_used * F_by_controller + BCP0_used
608:       ```
609:     - `FB` 的最终压力不得超过 `EB`
610:       - 若同一 `load_group × controller` 下出现 `BCP_FB > BCP_EB`
611:       - 则自动提高 `BCP0_EB`
612:       - 并重新计算 `EB` 的最终压力标准
613:       - 同时记录 warning 和 auto_adjustment
614:     - `BCP_calibrated_by_controller` 以 `[load_group × brake_type × controller]` 的三维结构输出
615: 
616: 9) `summarize_and_checks`
617: 
618: - in: all
619: - out: `report`
620: - 作用：汇总正式报告数据，供本地调试、Hermes 返回和 Markdown 导出使用。
621: - report 内容包括：
622:   - `brake_summary`：各 `brake_type` 的 `beta`
623:   - `load_summary`：各 `load_group × controller` 的 `mass_dynamic` 与 `spring_pressure`
624:   - `controller_pressure_standards` / `BCP_calibrated_by_controller`：各 `load_group × brake_type × controller` 的 BC 压力标准
625:   - `theoretical_speed_checks`：按 `V_list` 或默认 `v0` 输出 `FSB`、`EB`、`FB` 的理论速度检查值
626:     - `FSB`：使用其自身响应模型
627:     - `EB`：使用其自身响应模型
628:     - `FB`：控制目标减速度取 `Beta_EB`，但理论速度检查时使用 `FB` 自身的响应模型（`t1 + impulse_rate`）
629:     - `ratio_of_FSB` 类型不单独生成理论速度检查
630:   - `controller_code_params`：控制器开发用动态载荷公式和压力转换圆整参数
631:   - `calibration_summary`：标定试验点、生成的 `k_sb(f)` / `k_eb(f)`、`BCP0_sb` / `BCP0_eb`、以及 AW0/AW2/AW3 对应的 `k_for_code`
632:     - 对 Markdown 主视图：
633:       - 必须展示最终生效的 `BCP0` 与 `BCP0_for_code`
634:       - 必须展示输入标定点 `input_AW0 / input_AW2 / input_AW3`（按实际配置出现）
635:       - 必须展示最终曲线边界点 `curve_low / curve_high`
636:       - 必须明确区分“输入标定点”和“最终曲线边界点”
637:       - 必须展示 `k_for_code` 的分段公式与分段曲线图
638:       - 曲线图应体现“低段常数 + 中段线性 + 高段常数”，纵坐标按实际数据范围自适应，不强制从 0 起画
639:       - 若发生 `FB > EB` 自动调整，`emergency_brake` 下展示的 `BCP0` / `BCP0_for_code` 必须反映最终生效值，而非原始输入值
640:       - 当 `controller_type = car` 时，`emergency_brake` 不展示 `k_eb(f)` 标定曲线、分段 `k_for_code` 公式或标定后的 `BCP0_for_code`；应展示 V1.0 限制提示，并保留 EB 基础压力结果用于压力标准矩阵。
641: 
642:   - `parking_brake_check_result`：停放制动力校核结果，包括：
643:     - 每车双侧停放作用力 `F_N_PB`
644:     - 每车停放制动力 `F_PB`
645:     - 每车倾斜力 `incline_force`
646:     - 每车防滚安全余量
647:     - 整列停放制动力
648:     - 整列倾斜力
649:     - 整列防滚安全余量
650:     - 是否通过
651:     - `incline_force` 当前采用“坡道项 + 风阻项”口径
652:   - `parking_brake_check_results_by_load_group`：按 `grade_by_load_group` 逐载荷组输出正式停车校核结果；`parking_brake_check_result` 保留为兼容字段
653:   - `electric_brake_summary`：电制动特性输入摘要，仅展示识别后的特性点前若干项和末若干项，当前不参与主制动计算
654:   - `auto_adjustments`：自动调整记录，包括但不限于：
655:     - 超黏着后由 `equal_wear` 自动切换为 `equal_adhesion`
656:     - `FB` 压力超过 `EB` 后自动上调 `BCP0_EB`
657:   - `delta_BCP`、`warnings`、`clamp_events`、`trace`
658: - 报告显示精度：
659:   - 距离与 kPa 四舍五入到整数
660:   - 载重 ton 四舍五入到小数点后 2 位
661:   - 减速度四舍五入到小数点后 3 位

664: ## 7. pressure_calibration（试验点驱动的压力标定）
665: 
666: ### 7.1 默认基础换算
667: 
668: - 默认基础换算中的 `k_initial` 与 `BCP0_initial` 不作为用户输入显式配置，由 S7 根据 `mech_params` 与 `n_cylinders_by_controller` 推导。
669: - S7 理论基础压力为：
670:   ```text
671:   BCP_base = k_initial * F_by_controller + BCP0_initial
672:   ```
673: - `pressure_calibration` 仅描述输出侧调试标定参数，不覆盖 S7 的机械模型本体；V1 中标定输入采用“试验点驱动”结构，而不是直接配置完整分段曲线
674: 
675: ### 7.2 标定开关
676: 
677: - `pressure_calibration.enabled = false` 时，S8 不做调试标定：
678:   - `k_used = k_initial`
679:   - `BCP0_used = BCP0_initial`
680:   - `BCP_calibrated = k_used * F_by_controller + BCP0_used`
681: - `pressure_calibration.enabled = true` 时，S8 使用试验点驱动标定配置：
682:   - 常用/快速制动：由 `service_brake` 生成 `k_sb(f)` 与 `BCP0_sb`
683:   - 架控项目的紧急制动：由 `emergency_brake` 生成 `k_eb(f)` 与 `BCP0_eb`
684:   - 车控项目的紧急制动：V1.0 不应用 `emergency_brake` 标定，仍使用 S7 基础压力结果；车控 EB 实际 BCP 压力标定留待 V1.1
685: 
686: 
687: ### 7.3 标定参数的作用域
688: 
689: - `k_initial`、`BCP0_initial` 由 S7 机械模型推导，作为未调试状态的理论基础值
690: - 调试后的系数分为两套：
691:   - `k_sb(f)` / `BCP0_sb`：常用/快速制动体系
692:   - `k_eb(f)` / `BCP0_eb`：紧急制动体系
693: - `k_sb(f)` 与 `k_eb(f)` 表示实际使用的力-压力转换系数，单位均为 `kPa/kN`
694: - `BCP0_sb` 与 `BCP0_eb` 表示实际使用的初闸压力，单位均为 `kPa`
695: - 两套标定参数都为全列共享；每个 controller 使用自身 `F_by_controller` 查询同一套曲线
696: - `FSB`、`FB` 和 `ratio_of_FSB` 共用 `service_brake` 标定结果
697: - `EB` 独立使用 `emergency_brake` 标定结果
698: 
699: ### 7.4 标定输入配置（V1）
700: 
701: V1 中，`pressure_calibration` 不再要求用户直接维护完整的 `k_segments`。  
702: 用户输入的是**标定试验点**与固定 `BCP0`，由 S8 根据试验点自动生成分段 `k(f)` 曲线。
703: 
704: `pressure_calibration` 分为两组：
705: 
706: - `service_brake`
707:   - 生成常用/快速制动共用的 `k_sb(f)` 与 `BCP0_sb`
708:   - 架控与车控项目均适用
709:   - 适用于：
710:     - `FSB`
711:     - `FB`
712:     - `ratio_of_FSB`
713: - `emergency_brake`
714:   - 生成紧急制动独立的 `k_eb(f)` 与 `BCP0_eb`
715:   - 仅适用于 `controller_type = bogie`
716:   - V1.0 不适用于 `controller_type = car`
717:   - 适用于：
718:     - `EB`
719: 
720: 
721: 建议结构：
722: 
723: ```yaml
724: pressure_calibration:
725:   enabled: true
726:   service_brake:
727:     BCP0: 25.0
728:     point_pair_mode: aw3_aw0
729:     points:
730:       - load_group: AW0
731:         brake_type: FB
732:         k_for_code: 1050
733:       - load_group: AW3
734:         brake_type: FSB
735:         k_for_code: 1200
736:   emergency_brake:
737:     BCP0: 30.0
738:     point_pair_mode: aw3_aw0
739:     points:
740:       - load_group: AW0
741:         brake_type: EB
742:         k_for_code: 1100
743:       - load_group: AW3
744:         brake_type: EB
745:         k_for_code: 1250
746: ```
747: - 字段约束：
748:   - `enabled` = false 时，S8 不应用调试标定
749:   - `enabled` = true 时：
750:     - 当 `controller_type = bogie`：`service_brake` 和 `emergency_brake` 两组都必须配置
751:     - 当 `controller_type = car`：只允许配置 `service_brake`；不得配置 `emergency_brake`
752: 
753:   - 每组必须恰好提供两个试验点
754:   - `point_pair_mode` 仅允许：
755:     - aw3_aw0
756:     - aw3_aw2
757:   - `service_brake.points[].brake_type` 允许：
758:     - FSB
759:     - FB
760:   - `emergency_brake.points[].brake_type` 固定为：
761:     - EB
762:   
763: ### 7.5 标定曲线生成规则
764: 
765: #### 7.5.1 力坐标选取规则
766: 
767: - 每个标定试验点都要先映射到一个 controller force 坐标。
768: - 对给定 load_group + brake_type 工况，先计算该工况下所有 controller 的 F_by_controller，再按以下规则选取力坐标：
769:   - AW0：取各 controller force 的最大值
770:   - AW3：取各 controller force 的最小值
771:   - AW2：取各 controller force 的平均值
772: 
773: #### 7.5.2 支持的点组合
774: 
775: - V1 支持两种标定点组合：
776:   - aw3_aw0
777:   - aw3_aw2
778:   
779: #### 7.5.3 aw3_aw0 生成规则
780: 
781: - 当使用 aw3_aw0 时：
782:   - 由 AW0 点与 AW3 点形成主线性段
783:   - 在 AW0 力坐标以下，使用 AW0 点对应的常数 k
784:   - 在 AW0 与 AW3 力坐标之间，使用线性段
785:   - 在 AW3 力坐标以上，使用 AW3 点对应的常数 k
786:   - 因此最终生成的 k(f) 一定是：
787:     - 低力段常数
788:     - 中间线性
789:     - 高力段常数
790: 
791: #### 7.5.4 aw3_aw2 生成规则
792: 
793: - 当使用 aw3_aw2 时：
794:   - 先用 AW2 点与 AW3 点拟合主线性段
795:   - 但低力侧不能留空，因此必须外推到一个 AW0 参考力点
796:   - 外推得到 AW0 参考力点对应的 k 值后：
797:     - 在该参考力以下，使用外推点常数
798:     - 在参考力与 AW3 点之间，使用线性段
799:     - 在 AW3 点以上，使用 AW3 点常数
800:   - report / Markdown 必须同时展示：
801:     - 原始输入标定点 `input_AW2`、`input_AW3`
802:     - 外推后用于曲线边界的 `curve_low`
803:     - 高段边界点 `curve_high`
804:   - 文档中必须明确“输入标定点”与“最终曲线边界点”不是同一概念
805: 
806: #### 7.5.5 aw3_aw2 的 AW0 参考力规则
807: 
808: - 对 service_brake：
809:   - 若项目启用 FB，则 AW0 参考力取 AW0 + FB 工况下各 controller force 的最大值
810:   - 若项目未启用 FB，则 AW0 参考力取 AW0 + FSB 工况下各 controller force 的最大值
811: - 对 emergency_brake：
812:   - AW0 参考力取 AW0 + EB 工况下各 controller force 的最大值
813: 
814: #### 7.5.6 作用域规则
815: 
816: - k_sb(f) 与 BCP0_sb 的作用域为全列共享
817: - k_eb(f) 与 BCP0_eb 的作用域为全列共享
818: - 每个 controller 使用自身的 F_by_controller 查询同一套曲线
819: - FSB、FB 和 ratio_of_FSB 类型共用 service_brake 生成的曲线
820: - EB 使用 emergency_brake 生成的曲线
821: - 当 `controller_type = car` 时，以上 EB 使用 `emergency_brake` 曲线的规则不适用；V1.0 车控项目不生成、不应用 `k_eb(f)`。
822: 
823: 
824: #### 7.5.7 k_for_code 说明
825: 
826: - YAML 中输入的 k_for_code 为控制器开发口径数值。
827: - 在物理计算中，实际使用系数换算为：
828:   k = `k_for_code` / 100
829: - S9 仍需输出各载荷工况下的 k_for_code 值，供控制器开发使用
830: 
831: #### 7.5.8 车控 EB 标定限制（V1.0）
832: 
833: - 当 `controller_type = car` 时，V1.0 不支持紧急制动（EB）的 `k_eb(f)` 试验点标定。
834: - 车控 EB 的现场标定采用机械式实际 BCP 压力标定方法，不等同于架控 EB 当前使用的 `k_for_code / BCP0` 曲线标定。
835: - 因此 V1.0 中：
836:   - `pressure_calibration.service_brake` 仍可用于常用/快速制动体系；
837:   - `pressure_calibration.emergency_brake` 不得用于车控项目；
838:   - 车控 EB 的最终压力标准使用 S7 基础压力结果，并继续执行阀件限幅；
839:   - report / Markdown / 前端不得展示车控 EB 的伪 `k_eb(f)` 标定曲线或伪 `k_for_code` 分段公式；
840:   - 应明确提示“车控 EB 实际 BCP 压力标定 V1.0 暂不支持，需由开发人员线下处理；V1.1 接入”。
841: - 若 `controller_type = car` 且输入中配置了 `pressure_calibration.emergency_brake`，V1.0 应作为输入错误处理，不得静默套用架控 EB 标定逻辑。
842: 
843: 
844: #### 7.5.9 FB 与 EB 的干涉处理
845: 
846: - 快速制动 FB 使用常用制动体系的 k_sb(f) 与 BCP0_sb。
847: - 若标定后出现同一 load_group × controller 下：
848:   BCP_FB > BCP_EB
849:   则：
850:   - 必须自动提高 BCP0_EB
851:   - 并重新计算 EB 的最终压力标准
852:   - 同时写入 warning 与 auto_adjustment
853:   - `report.calibration_summary.emergency_brake.BCP0` 与 `BCP0_for_code` 必须写入最终提升后的生效值
854:   - 网页交互与报告中需明确提示：
855:     “快速制动压力超过紧急制动压力，已自动上调紧急制动初闸压力 BCP0_EB 并重新计算紧急制动压力标准。”
856: 
857: #### 7.5.10 覆盖性要求
858: - `controller_type`=bogie条件下，V1 生成的 k_sb(f) 与 k_eb(f) 必须覆盖完整有效力区间；`controller_type`=car条件下，k_sb(f)要求覆盖完整有效力区间；
859: - 不允许出现某个有效 controller force 落在曲线空档中、无法取得有效 k 值的情况
860: 
861: ## 8. Workflow（确定执行顺序）
862: 
863: > 每个 step 用一句 `desc` 说明作用，详细语义见第 6 节同名模块
864: > 
865: 
866: ```yaml
867: workflow:
868:   - id: s1
869:     use: validate_inputs
870:     desc: 校验输入结构与单位，填默认值，产出可信赖的 validated_inputs
871:   - id: s2
872:     use: derive_requirement
873:     needs: [s1]
874:     desc: 统一换算 requirement（平均减速度或制动距离）为 a_mean_req（运动学类型的平均减速度需求）
875:   - id: s3
876:     use: response_compensation
877:     needs: [s2]
878:     desc: 根据 FSB 的 `t1 + impulse_rate` 与 EB 的 `t1 + t2` 反求稳态目标减速度，产出 Beta_list（含 FSB/EB 运动学解、比例类型缩放）
879:   - id: s4
880:     use: calc_dynamic_load_and_mass
881:     needs: [s3]
882:     desc: 按 AW0/AW2/AW3 和转向架类型计算 Mass_by_controller（静态+含旋转质量的动态制动质量）,同时产出空簧压力标准和空簧拟合公式供调试/报告使用
883:   - id: s5
884:     use: calc_required_brake_force
885:     needs: [s4]
886:     desc: 结合 Beta_list、Mass_by_controller 与分配策略（EB 强制等黏着、FSB/比例类型按配置）得出 F_by_controller
887:   - id: s6
888:     use: allocate_brake_force
889:     needs: [s5]
890:     desc: 验证分配结果是否满足约束，统一结构粒度；越限则写入 warnings
891:   - id: s7
892:     use: force_to_pressure_base
893:     needs: [s6]
894:     desc: 用踏面制动缸机械模型（mech_params + n_cylinders_by_controller）将 F_by_controller 反算为未校准的 BCP_base_by_controller
895:   - id: s8
896:     use: apply_pressure_calibration
897:     needs: [s7]
898:     desc: 可选应用压力标定；架控项目按 load_group + brake_mode + controller force 选取 k(f)，按 load_group + brake_mode 选取 BCP0，计算最终 BCP_calibrated_by_controller 并执行限幅；车控项目 V1.0 仅开放 service_brake 标定，EB 不应用 emergency_brake 的 k(f) 标定，仍使用 S7 基础压力结果，车控 EB 实际 BCP 压力标定留待 V1.1。
899:   - id: s9
900:     use: summarize_and_checks
901:     needs: [s8]
902:     desc: 汇总压力标准、理论速度检查、控制器开发参数、告警、clamp 事件与 trace，生成结构化 report；CLI 可选导出 Markdown
903: ```
